## 2. Подробная инвентаризация по разделам

### 2.1. Раздел EDA (Exploratory Data Analysis — 15% оценки)
*Файл компонента:* `src/components/AcademicResearch.jsx`

#### Что сейчас реально:
1. Интерактивный Bento Grid интерфейс с переключением фильтров классов (`All`, `Hazards`, `Violations`).
2. Карточка пространственной калибровки `camera.md`:
   - Реальная математическая формула проекции на плоскость дороги: $[X, Y, 1]^T = H \cdot [u, v, 1]^T$.
   - Интерактивный переключатель точки контакта: обоснование привязки к колесам $(x_{mid}, y_{max})$ вместо геометрического центра бокса $(x_c, y_c)$ с устранением параллакса глубины.
   - Валидный JSON-контракт файла `camera.md` с полигонами стоп-линий, пешеходных переходов и векторами полос.
3. Интерактивный симулятор экстремального освещения (день 95 000 Lux, полночь < 5 Lux, мокрый асфальт) с кнопкой включения/выключения адаптивного фильтра CLAHE.
4. Бегущая строка технических ограничений хакатона (NVIDIA Tesla T4, Batch Size 1, Вес < 5 GB, Offline Mode, 25 FPS, $H=5.0$с горизонт).

#### Что сейчас стоит как МОК (Синтетические данные):
- **Частоты 14 классов:**
  ```javascript
  // Сейчас захардкожено в AcademicResearch.jsx:
  congestion: 42.4%, stopped_vehicle: 31.8%, following_too_close: 8.2%,
  solid_line: 5.1%, red_light: 3.4%, stop_line: 2.8%, speeding: 2.2%,
  illegal_turn: 1.4%, illegal_u_turn: 0.9%, wrong_way: 0.6%,
  jaywalking: 0.5%, near_miss: 0.4%, accident: 0.2%, fire_smoke: 0.1%
  ```
  *Проблема:* Это правдоподобное экспертное распределение (тяжелый хвост), но оно не посчитано по реальной разметке датасета хакатона.

#### Чего СОВСЕМ НЕТ (Прямые требования регламента):
1. **Тепловая карта движения (Motion Heatmap):**  
   В регламенте прямо указано: *«Графики/тепловые карты: плотность трафика по времени, распределение событий по типам»*. Сейчас на сайте нет ни одной визуальной тепловой карты трафика по полосам перекрестка.
2. **График суточной/временной плотности трафика (Traffic Density Curve):**  
   График распределения интенсивности транспортного потока (число ТС в минуту / час) по времени видео.
3. **Паспорт датасета (Dataset Meta Summary):**  
   Точные метаданные: общее количество предоставленных видео, суммарный хронометраж (в минутах), частота кадров (25 FPS), распределение по погодным условиям (день / сумерки / ночь).

### 2.3. Раздел Live Demo (30% оценки)
*Файл компонента:* `src/components/LiveDemoSection.jsx`

#### Что сейчас реально:
1. Полнофункциональный HTML5-видеоплеер с аппаратным ускорением (`<video id="player">`).
2. Клиентская валидация файла: проверка расширения (`.mp4`), проверка размера (`<= 50 МБ`), информационный бейдж ограничения длины (`≤ 2 мин`).
3. Трехшаговый индикатор выполнения согласно регламенту:  
   *«Шаг 1: Загрузка видео... → Шаг 2: Детекция событий... → Шаг 3: Формирование таймлайна»*.
4. Горячие клавиши: `Space` (Play/Pause), `F` или русская `А` (полноэкранный режим), двойной клик по плееру.
5. Интерактивный переход `jumpTo(time)`: клик на любое событие в списке мгновенно перематывает видео на его начало.
6. Синхронизированный график вероятности аварии $R(t)$ с динамической подсветкой аварийного порога $\tau = 0.50$.

#### Что сейчас стоит как МОК:
- При загрузке **нового произвольного видео от жюри**:
  - Таймер отсчитывает прогресс симуляции (от 0% до 100%).
  - Список обнаруженных нарушений берется из статического массива `defaultUploadEvents` (`following_too_close`, `solid_line`, `near_miss`, `stopped_vehicle`).
  - Кривая риска для загруженного видео генерируется синусоидой `Math.sin(...)`.
  - Поверх видео рисуются моковые bounding boxes из массива `defaultUploadBoxes`.
- *Причина:* В статическом приложении на Vercel нет привязанного GPU-сервера с запущенной нейросетью.

### 2.4. Раздел Архитектура и подход (15% оценки)
*Файл компонента:* `src/components/PlatformStack.jsx`

#### Что сейчас реально:
- Описание 4-уровневого пайплайна:
  - Слой 1: YOLO26m (NMS-free) — детекция ТС и пешеходов.
  - Слой 2: ByteTrack — межвекторное трекирование с фильтром Калмана и исправлением `fuse_score=False`.
  - Слой 3: Кинематические правила по `camera.md` — определение 14 классов интервалов.
  - Слой 4: Causal Risk Estimator — оценка риска на горизонте 5 секунд без заглядывания в будущее.

#### Чего СОВСЕМ НЕТ:
1. **Графическая блок-схема (Flowchart пайплайна):**  
   Регламент требует наглядную схему архитектуры:  
   `[Входное видео 25 FPS]` $\to$ `[CLAHE / Предобработка]` $\to$ `[YOLO26m NMS-Free]` $\to$ `[ByteTrack Ассоциация]` $\to$ `[camera.md Гомография]` $\to$ разветвление на `[Part A: Rule Engine (14 классов)]` и `[Part B: Causal Risk Estimator (H=5s)]` $\to$ `[predictions.json]`.
2. **Таблица "Learned vs Rule-Based":**  
   Требование регламента: *«обоснование выбора: что learned vs что rule-based»*. Нужно явно показать в виде сравнительной таблицы, почему одни компоненты обучены нейросетью, а другие сделаны на правилах.

### 2.5. Раздел Технический отчет и Ablation Study (10% оценки)
*Файл компонента:* `src/components/EngineeringReport.jsx`

#### Что сейчас реально:
1. Качественный инженерный анализ неудачных решений:
   - Тяжелые 3D CNN (Video Swin / SlowFast) — падение скорости до 6.2 FPS и вылет по памяти (OOM > 5 GB).
   - Оптический поток (Farnebäck / Lucas-Kanade) — 44% ложных срабатываний ночью из-за бликов фар на мокром асфальте.
   - Черный ящик LSTM для прогнозирования риска — переобучение на конкретные ракурсы дорожной разметки.
   - Одинарный порог IoU NMS — подавление стоящих машин в плотных заторах (решено переходом на NMS-free архитектуру).
2. Четкий план развития (What We Would Do Next): полуавтоматическая доразметка, ReID между перекрестками, INT8 квантование на Jetson.

#### Что сейчас стоит как МОК:
- Цифры в таблице абляционных исследований (`ablationData`):
  | Модель | Бэкбон | Трекер | FPS | VRAM | mAP@0.5 | Anticipation AP |
  | :--- | :--- | :--- | :---: | :---: | :---: | :---: |
  | YOLOv8-Nano Baseline | YOLOv8n | None | 82.4 FPS | 1.1 GB | 58.2% | 0.412 |
  | YOLOv8-Medium + SORT | YOLOv8m | SORT | 46.8 FPS | 2.6 GB | 68.7% | 0.584 |
  | **Our Pipeline: YOLO26m + ByteTrack** | **YOLO26m** | **ByteTrack + camera.md** | **44.8 FPS** | **3.2 GB** | **78.4%** | **0.762** |
  | RT-DETR-L + ByteTrack | RT-DETR-L | ByteTrack | 28.1 FPS | 4.8 GB | 74.1% | 0.695 |
  | Video Swin-Tiny (3D CNN) | Swin3D | End-to-End | 6.2 FPS | 5.9 GB (OOM) | 62.4% | 0.510 |
- *Проблема:* Эти показатели являются оценочными. Их необходимо синхронизировать с реальными метриками валидации, полученными Асаном в ходе экспериментов.

### Формат 1: Таймлайн событий для каждого сэмпла (от Асана)
```json
[
  {
    "start_sec": 14.5,
    "end_sec": 19.8,
    "label": "stop_line",
    "track": "White Sedan #22",
    "conf": 0.97,
    "desc": "Vehicle stopped past stop line on red signal",
    "type": "danger"
  }
]
```
*Типы событий (`type`):*
- `warning` (желтый): `stopped_vehicle`, `congestion`, `solid_line`, `following_too_close`

- `critical` (красный): `accident`, `near_miss`, `wrong_way`, `fire_smoke`, `failure_to_yield`
